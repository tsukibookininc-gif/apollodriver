# Первый тест на Mac — только обнаружение

Это исследовательская утилита, **не готовый звуковой драйвер**. Звук она не
включает, firmware/DSP не загружает, в UA Connect/Console карту не добавляет.
До этого все действия агента выполнялись в облаке; на вашем Mac ничего не запускалось.

## Сначала без скачивания файлов

1. Включите Apollo Twin X USB и подключите её к Mac кабелем USB 3.x для передачи данных.
2. Зажмите Option, откройте  → Информация о системе → USB.
3. Сообщите имя, Vendor ID, Product ID, скорость и версию macOS. Серийник не нужен.

Этого достаточно для первой проверки. Далее — необязательный запуск утилиты,
если вы сами решите скачать собранный в облаке архив.

## Если запускаете утилиту

Архив GitHub Actions содержит native ARM64 `apollo-inspect`, эту инструкцию,
LICENSE, BUILDINFO.json и SHA256SUMS. Нужен артефакт вашей версии macOS (15 или 26).
SHA в BUILDINFO.json указывает точный исходный код сборки. Это не installer,
системный компонент или фоновая служба.

После распаковки `.tar.gz` перейдите в Terminal в папку с `apollo-inspect`.
Контрольные суммы проверяются **из этой папки**:

```sh
shasum -a 256 -c SHA256SUMS
./apollo-inspect
```

Команда без аргументов только читает IORegistry и список Core Audio-устройств:
она не открывает USB-интерфейс и не отправляет USB-запросы. Результат печатается
в Terminal, отчёт на диск автоматически не записывается. Достаточно блока
`devices` и полей `macos`, `process_arch`, `usb_diagnostics_ok`; имя чужих
аудиоустройств/личные сведения можно не отправлять.

Следующая ступень, после просмотра первого результата:

```sh
./apollo-inspect --descriptors
```

Она получает сохранённые macOS USB-дескрипторы, без USBDeviceOpen и vendor commands.
Ошибки разбора сохраняются вместе с `raw_hex`; код завершения 2 означает ошибку
диагностики. `devices: []` означает, что целевые VID/PID не найдены; exit 0 сам по
себе не означает обнаружение Apollo. Флаги audio_streaming_implemented и
hardware_audio_verified остаются false при любом результате этой версии.

`--status` **не входит в первый тест**: этот режим открывает interface 0 и делает
известные IN-запросы, пока не проверенные на вашем Twin X. Для текущего результата
они не нужны. Параметров firmware/init/write/install в утилите нет.

## Если macOS блокирует запуск

Сборка имеет только ad-hoc подпись; Developer ID и notarization отсутствуют.
При блокировке сообщите точный текст. Не отключайте Gatekeeper/SIP, не снижайте
boot security и не удаляйте quarantine ради этого теста. Продолжить диагностику
можно через штатную «Информацию о системе», без этого файла. Утилите не нужны sudo,
перезагрузка, регистрация UA или установка системного компонента.

Результат теста — только наблюдение USB. Воспроизведение и запись пока не реализованы.
