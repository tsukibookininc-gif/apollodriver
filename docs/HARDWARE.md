# Аппаратная часть Twin X USB: свидетельства и пробелы

Исследовано 16 ноября 2026. Это анализ публикаций, не вскрытие устройства владельца.
Маркировка одного экземпляра не гарантирует ту же ревизию всех Twin X USB.

## Найденный разбор именно USB-модели

Первичная публикация ремонтной мастерской **Dhvan** от 3 февраля 2025 содержит
фотографии вскрытого [Apollo Twin X USB](https://dhvan-assistenciatecnica.blogspot.com/2025/02/interface-de-audio-universal-audio.html).
Просмотрены исходные фото CPU/DSP `IMG_2945.JPEG`, аналоговой платы `IMG_2946.JPEG`
и панели `IMG_2943.JPEG` / `IMG_2944.JPEG`. Фотографии не копируются в репозиторий.

| Блок | Свидетельство | Граница уверенности |
| --- | --- | --- |
| Два SHARC **ADSP-21489** | Маркировка на фото; UA подтверждает DUO SHARC в [описании модели](https://www.uaudio.com/products/apollo-twin-x-usb) | Версия модулей/ревизия DSP владельца неизвестны |
| FPGA **GOWIN**, семейство GW2A | Читается на CPU/DSP-плате | Полный suffix нечёткий; соединения и bitstream не установлены |
| MCU **ST ARM / STM32** | На фото видны логотипы и семейство | Полный part number и роль каждого управляющего сообщения не подтверждены |
| USB-мост семейства **Cypress/Infineon EZ-USB FX3** | Boot-протокол/формат образа в upstream; USB-чип виден на фото | Точная маркировка USB-чипа на фото недостаточно чёткая |
| Память, аналоговые I/O и панель | Видны отдельные микросхемы, платы и разъёмы | Точные модели АЦП/ЦАП и распайка не установлены |

На снимке CPU/DSP-платы наклейка `10006254 Rev 4`, шелкография
`PCB10007135 REV001`. Это сведения только о сфотографированном экземпляре.
Рабочая частота, адреса DSP и содержимое FPGA не следуют из названия SHARC.
Вскрывать карту владельца для разработки USB-драйвера сейчас не требуется.

## Сравнение с Apollo Twin X Thunderbolt

У той же мастерской есть [разбор Twin X от 3 июня 2024](https://dhvan-assistenciatecnica.blogspot.com/2024/06/interface-de-audio-universal-audio.html).
Просмотрены `IMG_1096.JPEG` (CPU/DSP) и `IMG_1102.JPEG` (задняя панель с обозначением
Thunderbolt). Это другой конкретный экземпляр/ревизия, не обобщение всех поколений.

| По фотографиям двух экземпляров | Twin X USB, публикация 2025 | Twin X Thunderbolt, публикация 2024 |
| --- | --- | --- |
| DSP | 2 × ADSP-21489 | 2 × ADSP-21469 |
| FPGA | GOWIN, семейство GW2A | Xilinx Spartan-6, XC6SLX45T |
| MCU | ST ARM / STM32, точный suffix не установлен | STM32F103, маркировка ZET6 |
| CPU/DSP-плата | Наклейка 10006254 Rev 4, PCB10007135 REV001 | Наклейка 10002886 Rev 6, 10003416 REV002 |

Для роли Spartan-6 сверена [страница производителя AMD/Xilinx](https://www.amd.com/en/products/adaptive-socs-and-fpgas/fpga/spartan-6.html),
а для второго DSP — [Analog Devices ADSP-21469](https://www.analog.com/en/products/adsp-21469.html).
Чипы 21469/21489 принадлежат SHARC: ADI сообщает о совместимости семейства по коду.
Это **не** гарантирует одинаковых memory maps, загрузочных ресурсов, FPGA-адресов
или порядка инициализации конкретных плат UA. Сходный DSP command language полезно
сравнивать, но firmware и USB transport необходимо проверять на целевой модели.

Сравнение показало, что различие этих плат шире замены внешнего разъёма. Фотографии
не доказывают невозможности своего драйвера и не исключают общего программного
кода UA. Достаточность изменения matching/VID/PID требует проверки реального
USB-кода и загрузочных путей драйвера; по фотографиям она не устанавливается.
Перестановка плат или физическая переделка не планируются.

[Каталог руководств UA](https://help.uaudio.com/hc/en-us/articles/13446310879892-Apollo-Hardware-Manuals)
даёт отдельный PDF Twin X USB. Сервер media.uaudio.com возвращал 403, поэтому полный
PDF/блок-схема не считаются независимо прочитанными первоисточниками в этой итерации.
Руководство из стороннего зеркала не скачивалось. USB 3, DUO и I/O сверены по странице UA.

## Документы производителей чипов

- [Analog Devices ADSP-21489](https://www.analog.com/en/products/adsp-21489.html)
  описывает SHARC, память и периферию, но не UA-протокол и адреса его DSP-модулей.
- [Infineon FX3](https://www.infineon.com/products/universal-serial-bus/usb-3-2-peripheral-controllers/ez-usb-fx3-usb-5gbps-peripheral-controller)
  описывает USB/ARM/GPIF-II мост. Связь GPIF-II с FPGA в Apollo правдоподобна,
  но не доказана по общему datasheet и этим фотографиям.
- [Infineon AN76405](https://www.infineon.com/assets/row/public/documents/30/42/infineon-an76405--ez-usb-fx3-fx3s-boot-options-applicationnotes-en.pdf),
  разделы 4.3–4.4: FX3 boot image использует длины в 32-битных словах, адреса,
  entry point и checksum. Это основа будущей офлайн-проверки собственного
  ApolloTwinX.bin. Нельзя механически копировать из upstream эвристику длины в
  байтах или пропускать checksum перед запуском образа. Загрузчик здесь не добавлен.

Штатный запуск должен согласовать USB firmware, DSP, маршрутизацию/clock и
изохронные потоки. Знание марки DSP не даёт точной последовательности. DSP-код
должен выполняться на самой карте: эмулировать SHARC на M5 для этого не нужно.

## Чем помогут Windows- и macOS-драйверы

| Материал из собственной установки | Что исследовать | Чего это не докажет |
| --- | --- | --- |
| Windows: UAD2Usb.sys, INF, ApolloTwinX.bin, capture именно Twin X | VID/PID, порядок control/bulk, тайминги, ответы, форматы | Пригодность init от Solo или старого Twin |
| macOS: UAD2System, Mixer Engine | Значения DSP-команд, mixer/routing, модельные таблицы, взаимодействие фирменного ПО с драйвером | Поддержку USB-модели или достаточность правки списка устройств |
| Apple USB/Core Audio SDK | Нативный транспорт, владение интерфейсами, clock/buffers и регистрация устройства | Возможность пересобрать Linux ALSA-модуль для macOS |

Упоминания CUAD2UsbDevice в upstream-анализе macOS — зацепка для изучения общего
кода, не подтверждение поддержки Twin X USB. Собственных бинарников/firmware
владельца в облаке нет; они **не исследовались**. Сторонние копии UA-драйверов не
скачивались. В дальнейшем допустим анализ собственной законно установленной
копии, без публикации ресурсов UA.

Проверен также [stepbrobd/uad2](https://github.com/stepbrobd/uad2): его README
описывает Linux ALSA/PCIe драйвер **Thunderbolt**, основанный на macOS kext.
Это материал по общей DSP-части, не USB/macOS port. Файлы из его bin/ не скачивались.

## Практический результат

По стандартным структурам [Linux USB Audio v2](https://github.com/torvalds/linux/blob/master/include/linux/usb/audio-v2.h)
сверены раскладки UAC2 и добавлен их разбор. Код Linux-драйвера не переносился.
Число USB-каналов, subslot и bit resolution нужно читать из дескрипторов карты;
маркетинговое «10×6» и число разъёмов их не заменяют.
В [libusb Darwin](https://github.com/libusb/libusb/blob/master/libusb/os/darwin_usb.c)
независимо сверены IOUSBLib API и cached descriptors. Это проверка выбранного API,
не доказательство работоспособности Apollo на M5.

Главные недостающие данные — дескрипторы/состояние реальной карты и model-specific
последовательность запуска с ответами. Пока достаточно штатного USB-дерева Mac;
загрузка firmware, записи команд и изменения безопасности исключены.
